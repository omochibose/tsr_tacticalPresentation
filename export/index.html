1-1 データパイプラインとは

あるシステムから別のシステムへデータを流す方法のこと。特定の順序で実行される一連のステップで構成され、あるステップの出力が次のステップの入力として機能する。

出典： databricks [データパイプラインとは何ですか？]

出典: Solon Das, 15 Real-World Data Pipeline Issues and How to Solve Them Like a Pro（LinkedIn, 2025.4.17）

1-2 なぜデータパイプラインが必要なのか

  • 先述の通り現場での分析は一度で完結しない（講義・研究を除く）
  • 手動で何度も同じ処理を行うのは非効率かつミスの温床
  • データパイプラインで自動化ができれば質を担保しつつその業務から開放される！
  • 一方で、ぶっちゃけ必要ではないし構築できる現職アナリストは少ない

[ちょっと脱線] 凡人は量で勝負！

  • 自分が凡人だと思う人は量で勝負しよう！
  • ただ残念なことに、いわゆる才能ある人たちは結構量もこなす
  • 我々に与えられている時間は平等に24時間。
  • では、どのようにすれば勝てる…？
  • 仕組みで時間を生み出し、空いた時間を考えることに使う！

1-3 データパイプラインの概要

  • 大まかなプロセス（工程）は以下の通り
    1. 収集
    2. 整形
    3. 保存
    4. 分析・可視化
  • 前回の振り返りで紹介した「分析サイクル」とは少し違う…？

分析サイクルとパイプラインの対応


分析サイクル パイプライン 対応
課題設定 前提 目的は人が決める
収集 収集 同じ
整形 整形 同じ
— 保存 新規
分析・可視化 分析・可視化 同じ
伝達 出口 誰に・いつ届けるか

  • 単発の分析では、データを「貯めておく」必要がなかった
  • 継続的に回すからこそ、前回までのデータを蓄積する「保存」が加わる

プロセスをつなぐ

  • 各プロセスを自動化の処理でつなぐことで、一気に成果物まで生成される
  • ただ、まずは一つのプロセスを自動で行えるところまでを目指そう

出典: Solon Das, 15 Real-World Data Pipeline Issues and How to Solve Them Like a Pro（LinkedIn, 2025.4.17）
